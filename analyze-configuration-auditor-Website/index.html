analyze-configuration-auditor

Audits system configurations, with SSH and Apache named as examples, against security best practices, and flags deviations. Rules arrive in YAML or JSON configuration files that define them.

Tag: Focused on Data analysis and reporting.

2

Second pocket: the rules file

The first argument is a rules file in YAML or JSON, and it must contain a top level rules list. Each rule is a mapping with four fields, set out here as four gouges in a row: the id, a short identifier, for example SSH-001; the description, what the rule requires, in plain text; the check, the exact text to search for in the system configuration file; and the severity, the severity label reported for the rule, for example High.

rules:
  - id: SSH-001
    description: Root login is disabled
    check: "PermitRootLogin no"
    severity: High
3

Third pocket: two working rules

A commented line is not a pass

Lines that start with the hash character are skipped, so a commented out setting does not count as a pass.

No rules, no report

An empty rules list is an error: the tool exits nonzero and writes no report, because no audit was performed.

4

Fourth pocket: the roll the studio ships

A rule set for OpenSSH server settings is included as sshd_rules.yaml, covering PermitRootLogin, PasswordAuthentication, and PermitEmptyPasswords.

python3 main.py sshd_rules.yaml /etc/ssh/sshd_config

Operators can supply their own rules files in the same format for other systems, such as Apache.

Fifth pocket: getting and running the tool

git clone https://github.com/ShadowGuard-AI/analyze-configuration-auditor
./analyze-configuration-auditor [params]
